# Hand-built U-Net: Training, Resuming, and Reviewing Results

## Understanding This Experiment

Rather than reinitializing the network, we reload the model and AdamW state saved after epoch 10, resume at epoch 11, and stop at **a cumulative total of 50 epochs**.

```text
Freeze the old epoch 10 checkpoint
          ↓ Restore model + optimizer
Epoch 11 → Validate → Log CSV/save best and last
          ↓
        ...
          ↓
Epoch 50 → Fix the validation-best model → Analyze curves
```

The old checkpoint has no RNG state, so the data shuffling order that would have been used in the next epoch cannot be restored. Resumed training uses and records seed 42; new checkpoints save the RNG state to support future resumption. Do not describe this as a fully reproducible experiment with a fixed seed from epoch 1.

## 1. Existing Artifacts That Must Be Preserved

- Original path: `outputs/checkpoints/best_model.pt`.
- Frozen copy: `outputs/baselines/unet_10ep/best.pt`.
- Do not move the old notebooks, data, or `data/nnunet/`, or rerun the existing workflows.
- The new run directory must not already exist; accidentally reusing a directory name should raise an error rather than silently overwrite it.

Run all commands below from the project root. **First check whether the run is already active; do not launch the full training command twice.**

## 2. Smoke Test (Not an Experimental Result)

Run the automated tests first:

```bash
.venv/bin/python -m unittest discover -s tests -v
```

In a separate directory, check the pipeline with the actual checkpoint using one training batch and one validation batch:

```bash
.venv/bin/python -u -m camus_segmentation.train \
  --resume outputs/baselines/unet_10ep/best.pt \
  --epochs 11 --seed 42 --device cuda \
  --run-dir outputs/runs/smoke_resume10 \
  --smoke-test
```

This does not complete a full training epoch. Check that the original weights are unchanged, the AdamW step count continues, and the files can be reloaded. Do not use `smoke_test` artifacts as the starting point for the full resumed run; that run must still start from the frozen epoch 10 checkpoint.

## 3. Full Resumed Training to a Total of 50 Epochs

```bash
.venv/bin/python -u -m camus_segmentation.train \
  --resume outputs/baselines/unet_10ep/best.pt \
  --epochs 50 --seed 42 --device cuda \
  --run-dir outputs/runs/unet_resume10_to50_seed42
```

`--epochs 50` specifies the target total, not “50 more epochs.” Keep the model, batch size, input dimensions, loss, and AdamW hyperparameters as configured in the checkpoint; do not also change augmentation, the scheduler, or AMP. Resumption arguments that conflict with the source configuration should be rejected.

Training uses only the train/validation splits; the test split is not evaluated after each epoch. The full run writes `train.log`, so there is no need to rely on saved notebook output.

## 4. Files in a Run

| File | Purpose |
|---|---|
| `config.json` | Parameters for this training segment, source checkpoint, code/environment/split identifiers, etc. |
| `baseline.pt` | Frozen copy of the original baseline, not replaced by this training segment |
| `baseline.json` | Source baseline metrics; the old checkpoint provides only one saved point, not a complete historical curve |
| `best.pt` | Selected by validation mean foreground Dice; retains the existing best model if no later model improves on it |
| `last.pt` | Most recently completed training state, including the optimizer and RNG; used for resumption |
| `history.csv` | Actually recorded per-epoch loss, per-class Dice, step counts, learning rate, and elapsed time for this segment |
| `train.log` | Human-readable run log |
| `summary.json` | Summary after normal completion; its target epoch alone does not establish that training has completed |
| `curves.png` | Curves generated by the plotting command |

`history.csv` does not fabricate the missing training curves for epochs 1–10. The known epoch 10 validation metrics are plotted as separate baseline points.

## 5. Review Curves Without Repeatedly Tuning on the Test Set

After at least one full epoch has completed, or after training has finished:

```bash
.venv/bin/python -m camus_segmentation.plot_history \
  --run-dir outputs/runs/unet_resume10_to50_seed42
```

If `curves.png` already exists, explicitly add `--overwrite` to update it; this option applies only to plotting, not to overwriting training directories.

- Training loss falls and validation Dice rises: a larger training budget may still help.
- Training loss falls and validation Dice keeps falling: watch for overfitting and use the validation-best checkpoint.
- Both plateau: investigate learning rate or optimization issues separately rather than automatically adding epochs.
- Improvement in a single run does not establish consistent gains across multiple seeds; comparisons with nnU-Net across different grids remain pipeline comparisons.

## 6. Resuming After an Interruption

1. Confirm that the original training process has exited.
2. Check that the source run's `last.pt` corresponds to the most recently **completed** epoch, rather than relying only on the epoch shown as running in the log.
3. Leave the source run intact and resume with the same total budget in a **new directory**:

```bash
.venv/bin/python -u -m camus_segmentation.train \
  --resume outputs/runs/unet_resume10_to50_seed42/last.pt \
  --epochs 50 --device cuda \
  --run-dir outputs/runs/unet_resume10_to50_part2
```

A complete checkpoint restores its random state; changing `--seed` does not turn a resumed experiment into an independent new-seed run. Do not move `last.pt` on its own and lose the historical best model and provenance files in the same directory. The new directory records a new experimental segment; trace back to parent runs when reviewing the full curve, and do not present interpolated missing segments as actual results.

If an interruption occurs mid-epoch, updates from that unfinished epoch are not part of the persisted `last.pt`; resumption continues from the last completed epoch. Once 50 epochs have been completed, do not resume again with the same target.

## 7. Explicitly Evaluate a Selected Model

Inspect the validation split first (not the test split):

```bash
.venv/bin/python -m camus_segmentation.evaluate_test \
  --checkpoint outputs/runs/unet_resume10_to50_seed42/best.pt \
  --split validation \
  --output-json outputs/runs/unet_resume10_to50_seed42/validation.json
```

Only after fixing the model and comparison protocol should you manually run the final test evaluation:

```bash
.venv/bin/python -m camus_segmentation.evaluate_test \
  --checkpoint outputs/runs/unet_resume10_to50_seed42/best.pt \
  --split test \
  --output-json outputs/runs/unet_resume10_to50_seed42/test.json
```

Do not conflate validation and test results. Evaluation retains the checkpoint's input dimensions and the original resized-grid protocol; it does not automatically become an evaluation in the original physical space. Do not overwrite the source checkpoint with JSON or image outputs; use new names if outputs already exist.

Visualize a selected validation image:

```bash
.venv/bin/python -m camus_segmentation.visualize_prediction \
  --checkpoint outputs/runs/unet_resume10_to50_seed42/best.pt \
  --sample-index 0 \
  --output outputs/runs/unet_resume10_to50_seed42/validation_example.png
```

The legacy inference command without an explicit checkpoint still points to the historical 10-epoch model; it does not guess which run is the latest. The standard visualization command does not automatically replace the curated images in the README.

## 8. nnU-Net Is Outside the Scope of This Resumed Run

The existing nnU-Net configuration, preprocessing, weights, and predictions remain in `data/nnunet/`. See the [notebook guide](../notebooks/README.md). This work does not retrain nnU-Net, clear its outputs, or overwrite the old comparison table with results from the resumed hand-built U-Net run.
